# The astro-kit standard

Generated from `src/registry.ts` by `npm run docs`. Do not edit it by hand.

## How to read a result

Every failing check prints the same three lines:

```text
✗ [<id>] <where>: <message> (<detail>)
    fix: <hint>
    rule: node_modules/@raess/astro-kit/docs/standards.md#<id>
```

- The id in brackets is the rule below. Then come the place, the meaning and the value found.
- `!` in place of `✗` is a warning. It fails nothing now, and its message says when it becomes an error.
- `~` is a finding that a waiver in `astro-kit.json` covers, with its end date and its reason.
- Fix the cause. Never silence a check. If a check looks wrong, add an entry to `KIT-FEEDBACK.md`.

It is the only 404 page: no other built page path has a segment that is exactly `404`. Message for such a path `<p>`: `<p> has a 404 segment. Under build.format 'directory' it is written to <p>index.html, an ordinary page that answers 200. Cloudflare answers a missing URL only with a file named 404.html, which Astro builds only from src/pages/404.astro. Put every language on /404.html.` `/404.html` links every locale home (`/` and each `/<code>/`; a link to the file of a built home, `/fr/index.html`, counts too). It holds no form whose action starts with `/api/forms/`, because the `return` of such a form would fail. It passes every page rule that does not exempt it. Fix: Build every language on one `src/pages/404.astro`, which Astro writes to `/404.html`, and remove every other `404` page. Link each locale home from it, and put no form on it.
- <a id="routes-slug"></a>**routes-slug** — Every built page path other than `/404.html` ends in `/` (`…/index.html`), and each of its segments matches `^[a-z0-9]+(-[a-z0-9]+)*$`. A default-locale path does not start with a locale code or a reserved segment (`_astro`, `_actions`, `_server-islands`, `_image`, `_kit`, `api`, `500`, `.well-known`). A non-default path has no reserved segment after `/<code>/`. A `404` segment is left to `routes-404`, so it reports once. **The endpoint clause,** checked on the resolved routes: a project route of type `endpoint`, other than the form shim, is a static file route. Its pattern ends with a literal file extension `.<ext>` (`[a-z0-9]+`) that is not `html` or `htm`. Its first segment holds no parameter (`[`) and is not a reserved segment. When the first segment is a locale code, the second segment holds no parameter and is not a reserved segment. A parameter can stand for any name, so the kit cannot know which file it writes there. For example, `/[name].txt` and `/[dir]/[file].json` fail, and `/live.json` and `/feeds/[lang].json` pass. Its pattern is none of `/robots.txt`, `/_headers` and `/_redirects`, and no `/sitemap*.xml`. So a project endpoint can never write the file of a page or a file that the kit writes. `routes-on-demand` still requires it to be prerendered. Fix: Rename the page so that each segment has only lower-case letters, digits and single hyphens, and starts with no reserved segment. Give an endpoint a fixed first segment and a file extension other than `.html`.
- <a id="routes-translation"></a>**routes-translation** — Every non-default-locale page lists a default-locale alternate. In a `coverage: "full"` locale, every indexable default-locale page lists an alternate in that locale. An alternate is listed when its `hreflang` equals the tag in any ASCII case; a tag in another case is left to `hreflang-reciprocal`. `/404.html` is exempt. Fix: Build the missing page in that locale, and list each page as an hreflang alternate of the other. A page of another locale needs its default-locale sibling.
- <a id="routes-redirects"></a>**routes-redirects** — `redirects.json` rows are `{from, to}` or `{from, gone: true}`. `from` starts with `/` and has no whitespace, no `?` ("query strings cannot be matched; mark it gone or add a zone Single Redirect") and no `#` ("fragments cannot be matched: a browser never sends the text after #"). No duplicate `from`. `to` starts with `/`, not with `//` or `/\`, and has no whitespace, so a row writes one line and never leaves the site. Neither `from` nor `to` holds a backslash, and neither path holds a `.` or `..` segment, also not as `%2e`: Cloudflare removes such a segment, so it would store another path, and a `to` such as `/.//host/` would leave the site. The path of a `to` ends before its `?` or `#`. No chains (the path of no `to` is a `from`). Limits: 2,000 static, 100 dynamic, 1,000 characters per line. Every literal `to` is built (patterns, and `/api/` with forms, are skipped). Fix: Fix the row that the finding names. Point each `to` at a built page, or mark the row `gone`.

### head

- <a id="head-canonical"></a>**head-canonical** — Each non-404 page has exactly one canonical equal to `<site><path>` (the `site` setting and the page path), ending in `/`. The canonical, the description and the Open Graph tags are children of `head`: search engines and share scrapers read them only there, so one in `body` counts as none. Fix: Write one `<link rel="canonical">` with the absolute URL of the page, with its trailing `/`.
- <a id="head-lang"></a>**head-lang** — `html lang` equals the tag of the URL's locale. Fix: Set `<html lang>` to the `tag` of the locale that the first segment of the path names (`astro-kit.json` `locales`).
- <a id="head-title"></a>**head-title** (waivable) — 15–70 code points (`titleMin` and `titleMax`), unique per locale; `/404.html` exempt. Fix: Write a title of 15 to 70 characters that names this page and no other.
- <a id="head-description"></a>**head-description** (waivable) — 50–160 code points (`descriptionMin` and `descriptionMax`), unique per locale; `/404.html` exempt. The description is the one `meta[name=description]` child of `head`. Fix: Write a description of 50 to 160 characters that says what this page offers.
- <a id="head-og"></a>**head-og** (waivable) — Each non-404 page has `og:title`, `og:description`, `og:url` = canonical, and `og:locale` = tag with `-`→`_` (`de_CH`). `og:image` is optional. When a page has one, it is under `<site>/`, is a dist file ≤ 153,600 B (raw, `ogImageBytes`), and has `og:image:width` 1200 and `og:image:height` 630. A tag is a `meta` child of `head`. When a name appears twice, the first tag counts; every `og:image` is checked. One finding lists every problem. Fix: Write `og:title`, `og:description`, `og:url` (the canonical URL) and `og:locale`. A share image is a 1200×630 file of the site of at most 150 KB, with `og:image:width` and `og:image:height`.
- <a id="head-icons"></a>**head-icons** — Every page, 404 included, links `/favicon.ico`, `/icon.svg` and `/apple-touch-icon.png` (rel `icon` or `apple-touch-icon`), and the files exist. Fix: Link `/favicon.ico` and `/icon.svg` with `rel="icon"` and `/apple-touch-icon.png` with `rel="apple-touch-icon"`, and keep the three files in `public/`.
- <a id="head-jsonld"></a>**head-jsonld** (waivable) — Every JSON-LD block parses, and every node has an `@type`. No node, at any depth, has the type `AggregateRating`, `Review`, `EmployerAggregateRating`, `ClaimReview`, `HowTo` or `SpecialAnnouncement`, or an `aggregateRating`/`review` property. One organization `@id` is shared across pages. The organization node (`Organization` or the `site.json` type; a subtype of either is not the organization node) has `name`, `legalName`, `email`, `telephone`, `vatID`, `taxID` (uid), address (street, postal code, locality, region, country), `openingHoursSpecification` (= openingHours) and `specialOpeningHoursSpecification` (= closures as day ranges 00:00–00:00) equal to the facts when it states them; its `sameAs` ⊆ site.json `sameAs`. Every `Offer` `price` equals a `site.json` price amount in major units: a number or a text of digits with at most two decimals after a `.`, in the `priceCurrency` of the offer when it states one. A `WebPage` node, or a node of a schema.org subtype of `WebPage`, has `inLanguage` equal to the tag. `WebSite` appears only on locale homes. Fix: Build the JSON-LD from `site.json` and `schedule.json`, use one organization `@id` on every page, and leave out ratings, reviews and the banned types.

### headings

### hreflang

- <a id="hreflang-reciprocal"></a>**hreflang-reciprocal** — Alternates name configured tags (or `x-default`), exactly as configured, once each, are absolute under `site`, include the page itself, and point to emitted pages of the locale that the tag names, which list this page back. A page with no alternates is skipped. Fix: List one alternate for each locale of the page, itself included, with the absolute URL of a built page that lists this page back.
- <a id="hreflang-x-default"></a>**hreflang-x-default** — `x-default` equals the page's default-locale alternate: both name the same page path. A page with no alternates, such as `/404.html`, is skipped. When either href is not an absolute `https` URL of the site without a query, that href is `hreflang-reciprocal`'s, and the two are not compared. Fix: Add `<link rel="alternate" hreflang="x-default">` with the URL of the default-locale alternate.

### indexing

- <a id="indexing-noindex"></a>**indexing-noindex** — No page other than `/404.html` carries `noindex` (or `none`) in a robots meta: a `meta` whose `name` is `robots`, `googlebot`, `googlebot-news` or `bingbot`, in any letter case, since each search engine obeys the meta of its own crawler too. `/404.html` carries it in `meta[name=robots]`, for every crawler, when it exists. A missing `/404.html` is reported only by `routes-404`. Fix: Remove `noindex` from every page but `/404.html`, and add `<meta name="robots" content="noindex">` to `/404.html`. A page that must not be found does not belong in the build.

### links

- <a id="links-resolve"></a>**links-resolve** — Every same-origin href other than a fragment-only `#id` equals, byte for byte, an emitted page path or a dist file. A fragment-only href names an id on the same page. An absolute one uses https. It is not a redirect source. Its fragment exists on the target. Fix: Link the built path itself, with its trailing `/` (`/zimmer/`), and an `id` that exists on the target page.
- <a id="links-generic"></a>**links-generic** (waivable) — Every link has an accessible name: the first that is not empty of the text of the elements that `aria-labelledby` names, `aria-label`, the link's text (a descendant with a non-empty `aria-label` counts as that label, an `img` as its `alt`, an `svg` as the text of its `title` child, a hidden descendant (`aria-hidden="true"` or `hidden`) and template content as nothing, and the text of a block stands between spaces), and the `title` attribute, with white space collapsed and trimmed and read up to 1,000 characters. Lower-cased and trimmed of non-letters, the name is not one of: here, click, click here, more, read more, learn more, link, hier, klicken, hier klicken, mehr, weiterlesen, mehr erfahren, ici, cliquez, cliquez ici, plus, lire la suite, en savoir plus, qui, clicca qui, di più, scopri di più, leggi tutto. - <a id="links-same-name"></a>**links-same-name** (waivable) — Links with the same accessible name on a page share one target (path plus fragment). Fix: Give each link a name that tells its target apart, or point both links to the same target.

- <a id="links-depth"></a>**links-depth** (waivable) — Each locale home (`/`, `/<code>/`) exists when that locale has pages. Every indexable page is within 3 clicks (`clickDepth`) of its locale home (breadth-first over same-origin links). A link to the file of a built page (`/zimmer/index.html`) is a link to the page, as `links-resolve` accepts it. Fix: Build the home of each locale, and link the page from its home or from a page near it, for example from the sitemap page.

### facts

- <a id="facts-value"></a>**facts-value** (waivable) — Every email, phone number, CHE-UID, IBAN and CHF amount on a page equals a `site.json` value, including `contacts`. Swiss phones written `+41`, `0041` or `0` are normalized to E.164. CHF is compared in minor units against `prices` amounts. `mailto:` and `tel:` hrefs are checked too. Every Unicode space separator counts as a normal space, and each run of white space as one space, in the page text and in the `site.json` values alike. - <a id="html-validate"></a>**html-validate** (waivable) — Every page passes html-validate with only the kit config: `html-validate:recommended` and `html-validate:document`, elements `html5`; `unique-landmark`, `prefer-native-element` and `no-missing-references` are errors; `heading-level`, `wcag/h37`, `long-title` and `no-inline-style` are off; `require-sri` targets `crossorigin`, except a `script` whose `src` is on a host with `script` and `load: "page"`. html-validate reads the file as written, a UTF-8 byte order mark included. A page with more than 4 × `domElements` elements or a depth over 4 × `domDepth` (the kit's limits, template content counted) is not validated, because html-validate takes seconds on it or overflows its stack: it fails with one finding that says so. Fix: Fix the markup at the place that html-validate names. The detail holds its rule id and its message.
- <a id="html-shell"></a>**html-shell** — The first focusable element (`a[href], area[href], button, input:not([type=hidden]), select, textarea, summary, iframe, [tabindex]:not([tabindex="-1"]), [contenteditable], audio[controls], video[controls]`) is a skip link `a[href="#<id>"]`, and the page's single `main` has that id (the fragment as written or percent-decoded). Fix: Make the first focusable element of the page a link `<a href="#main" class="visually-hidden">` to the `id` of its one `<main id="main">`.

### legal

- <a id="legal-pages"></a>**legal-pages** — Each declared legal note, privacy and accessibility path is a built page of its locale. Every indexable page links its own locale's legal note and privacy paths (the path, or the file of that page). Fix: Build each legal page at its path in `astro-kit.json` `legal`, and link the legal note and the privacy page of the locale from every page, for example in the footer.
- <a id="legal-processing"></a>**legal-processing** — `processing` contains `cdn` and `previews`, and with forms `forms` and `server`; it contains `forms`/`server` only with forms. Fix: List `cdn` and `previews`. List `forms` and `server` with `features.forms`, and only then.
- <a id="legal-statement"></a>**legal-statement** (waivable) — A declared accessibility page claims conformance (a match of `konform`, `conforme`, `conformant` or `compliant`) only when `site.json` has `accessibilityAudit`. ### media

- <a id="media-animated"></a>**media-animated** (waivable) — No animated image ships: a GIF with more than 1 frame, an APNG (acTL before IDAT), a WebP with an ANIM chunk, or an AVIF with the `avis` brand. The format comes from the bytes, as a browser picks its decoder: every dist file is read except the text files (`.html`, `.htm`, `.css`, `.js`, `.mjs`, `.cjs`, `.map`, `.json`, `.txt`, `.xml`, `.svg`, `.webmanifest`), whatever its extension, or none. Fix: Replace the animation with a still image, or with a `video` that has captions and that the visitor starts.
- <a id="media-captions"></a>**media-captions** (waivable) — Every `video` has a `track[kind=captions]` child with `srclang` equal to the tag or code (a browser reads only the `track` children). Every `audio` is followed (next sibling, or the parent's next sibling) by a link whose accessible name or `href` matches `/transcript|transkript|transcription|trascrizione/i`. Fix: Add `<track kind="captions" srclang="<tag>">` to the video, and a link to the transcript right after the audio.
- <a id="media-pdf"></a>**media-pdf** (waivable) — Every `.pdf` in dist is a key of `site.json` `documents`, its value is a built page path, and that page links the PDF. Fix: Declare the PDF in `site.json` `documents` with the page that offers it, and link it from that page, or remove the file.

### a11y

- <a id="a11y-focus"></a>**a11y-focus** (waivable) — The first Tab and every sweep stop show `outline-style` other than `none` and `outline-width` ≥ 2 px, and a ring with a contrast of at least 3:1 against the color behind it (WCAG 1.4.11). In each declared theme that a fresh tab does not show, at 1280×800, each stop takes the focus in turn and its ring color is measured again; an element that the fresh 1280×800 tab reported is not reported again in another theme. A mouse click on a link, button or summary shows `none` or 0. A sweep is the Tab sequence of `a11y-keyboard`, through its stops, in each state of that rule. A press that leaves the focus on a part that the browser draws inside a control (the picker button of a date field, the volume of a player), where the control does not match `:focus`, is not measured, and neither is an `iframe`. Fix: Give `:focus-visible` an outline of at least 2 px in the focus color (for example `outline: var(--line-2) solid var(--color-focus)`), never override its color in a component, and never set an outline on `:focus` alone.
- <a id="a11y-targets"></a>**a11y-targets** (waivable) — At 1280×800 and 390×844, and after the reveal step at 390×844 (every visible `details` open, every target of a visible `[popovertarget]` or of a visible `[commandfor]` with `command` `show-popover` or `toggle-popover` shown, and each `dialog` target of `[commandfor][command=show-modal]` opened by itself): `a[href]` (except a link inline in text: climbing from its parent through the inline elements of `links-generic` up to the nearest ancestor that is not inline, one of these elements has a text node of its own with a letter or a digit), `button`, `input` (except checkbox, radio, hidden), `select` and `summary` are ≥ 43.5×43.5. Boxes ≤ 1×1 and boxes above the page start are skipped. Fix: Give the control a block size and an inline size of at least `2.75rem` (for example with padding), or put the link inline in a sentence.
- <a id="a11y-reflow"></a>**a11y-reflow** (waivable) — At 320×640, before and after the reveal step at 390×844 (every visible `details` open, every popover of a visible invoker shown, and each `show-modal` dialog opened by itself): no element's right edge exceeds `clientWidth + 1` unless an ancestor scrolls, and `scrollWidth ≤ clientWidth + 1`. An element with the kit class `visually-hidden`, and every element inside it, is skipped. Fix: Let the content wrap: use the layout helpers, `max-inline-size: 100%` on media, and `overflow-wrap: anywhere` for long words. Put a wide table in a container that scrolls.
- <a id="a11y-spacing"></a>**a11y-spacing** (waivable) — With `* { line-height: 1.5 !important; letter-spacing: .12em !important; word-spacing: .16em !important } p { margin-bottom: 2em !important }` at 1280 and 390 px, no element with `overflow-y` hidden or clip that holds a text node with a letter or a digit (outside `script`, `style` and `.visually-hidden`) has `scrollHeight − clientHeight > 2`. An element with the kit class `visually-hidden` is skipped, and so is every element inside it: the class clips text in a 1 px box on purpose. Fix: Do not fix the block size of a box that holds text, and do not hide its overflow: let it grow with its text.
- <a id="a11y-forced-colors"></a>**a11y-forced-colors** (waivable) — With forced colors active: `h1` and `main` are visible; every button (`button`, `input[type=button|submit|reset]`, `[role=button]`) has a border with style not `none`, width ≥ 1 px and a color that is not transparent, at 1280×800, at 390×844 and in each state of the reveal step; the first Tab of the fresh 1280×800 tab shows a focus ring. Fix: Give every button a border of at least 1 px (`transparent` in the normal theme is fine: forced colors paint it), and do not hide content with colors alone.
- <a id="a11y-keyboard"></a>**a11y-keyboard** (waivable) — At 1280×800, 390×844 and 390×844 after the reveal step (every visible `details` open, every popover of a visible invoker shown, and each `show-modal` dialog opened by itself, with a sweep of its own), Tab reaches every visible control within stops + 5 presses. The stops are the visible elements of the Tab sequence, where a radio group counts as one, plus each control that a negative `tabindex` keeps out of it (a composite widget with a roving `tabindex` counts once, with its group) and each scroll container that Chromium puts into it. A press that leaves the focus on the same element does not count, up to 50 in a sweep. No focused element is entirely covered: the center and the four corners, inset 2 px, of each on-screen line box are sampled with `elementFromPoint`. Fix: Use native controls in the order of the page, never a positive `tabindex`, and keep a sticky header from covering the focused element (`scroll-padding-block-start`).
- <a id="a11y-no-js"></a>**a11y-no-js** (waivable) — With JS off, `h1` and `main` are visible, and every link target and named control visible with JS on, except `[data-mode-switch]` and its content, is visible with JS off (both after the reveal step). Each declared form is filled and submitted within 10 s: email `probe@example.com`; tel `+41441234567`; date today + 30 days; number its `min`; choice its first option; consent checked; text and textarea `Kit browser test`. It must land on `<page path>#sent` with `#sent` visible. Before it fills a form, a fresh tab with JS off opens every `details` and popover, as the reveal step does, and then the dialog that holds the form, with a click on its visible native invoker (`[commandfor][command=show-modal]`). A form in a dialog that no visible invoker opens fails. Fix: Render the content and the controls in HTML, and let a script only add to them. A form posts as plain HTML and returns to `#sent`.
- <a id="a11y-reveal"></a>**a11y-reveal** (waivable) — Hidden UI opens only through native invokers (`summary`, `[popovertarget]`, `[commandfor]`). An element with `aria-expanded` or `aria-controls` that is none of those fails, unless it is inside an `astro-island`. Fix: Use `<details>` with `<summary>`, a `popovertarget` button or a `commandfor` button, so that the browser opens the content without a script.
